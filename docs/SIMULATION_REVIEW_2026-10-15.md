## 3. 통계에서 드러난 문제와 실제 수정

1. **화폐·식량의 과도한 증가:** 인구수에 비례한 자동 현금 유입을 없앴다. 임금은 공공재정 또는 민간시장 재원에서 지급하며, 식량과 상품 수출로 발생한 유입을 별도 기록한다.
2. **근무·세금 계산 오류:** 하루 여러 번 급여를 지급하던 문제를 제한하고, 정상적인 세후 지급액을 체불로 잘못 기록하던 오류를 바로잡았다. 소액 임금의 세금이 내림 처리로 0이 되는 문제도 수정했다.
3. **국고 고갈과 시장 유동성 부족:** 소득·소비에 따른 세금을 기록하고, 국고가 있을 때의 공공 정비 계약과 제한적인 긴급 식량 지원을 추가했다.
4. **농부도 굶는 모순:** 농부가 생산한 식량 일부를 개인 비축용으로 남기고, 먼저 자가 소비하도록 변경했다. 신뢰하는 친구가 식량을 나눠주는 행동도 추가했다.
5. **무한 무상 지원:** 친구의 긴급 금전 지원을 대여금으로 관리하며 상환·연체·거절 규칙을 추가했다. 가까운 친구의 집에 잠시 머무는 생존 경로도 제공한다.
6. **항상 비슷해지는 인구:** 마을마다 다른 거주 수용력을 정하고 그 수준과 경제 상황을 바탕으로 이주 가능성을 제한했다. 생존이 어려운 사람은 다른 지역으로 떠날 수도 있다.
7. **변하지 않는 직업:** 저축과 성향이 맞으면 창업하고, 사업 파산이나 급료 체불 시 직업을 바꿀 수 있는 일부 경로를 추가했다.
8. **사망 시 재산 소멸:** 가까운 수익자에게 재산 일부가 넘어가거나 국고로 귀속되는 임시 상속 규칙을 구현했다.
9. **지나친 노화:** 주민이 12일마다 한 살씩 늙던 오류를 수정해 365일을 1년으로 다룬다.

## 4. 추가 장기 검증과 남은 문제

1년(365일) 장기 검증에서는 최신 부근 모델 10개 시드의 평균 누적 사망이 약 13명, 굶주림 관련 사망이 약 8명이었다. 작은 마을 기준으로 여전히 매우 높은 사망률이다. 다만 잔혹하고 위험한 세계관이라는 게임 의도를 고려하면 단일한 현실 평균에 맞추기보다는 '안정된 마을'과 '혼란스러운 마을'의 사망률이 충분히 구분되는지가 다음 평가 대상이다.

현행 시장은 아직 하나의 공동 결제 계정에 가까워 개별 상점, 가계 장부, 가격·재고가 완전히 분리되지 않았다. 주민의 직업 이동과 사업 설립도 일부 규칙에 한정되고, 가족·자녀·상속권·인접 왕국의 실제 공급망은 미구현이다. 또한 관계 판단은 확률 및 상태 기반이어서 현실 인간의 의사결정을 대체하지 않는다.

## 5. 다음 개선 우선순위

1. **사업체별 독립 장부:** 상인·여관·농장의 수익, 인건비, 재고, 임대료가 각자의 재무 상태에서 결정되도록 재구성. 시장 총액이 임금을 곧바로 지급하는 구조 축소.
2. **생존 계획:** NPC가 오늘만이 아니라 며칠 뒤의 식비와 주거비를 예상하고 취업·대출·이주·범죄를 선택하도록 설계.
3. **위험도 구분:** 사고·범죄·굶주림·질병 사망을 세부 원인별로 나누고 왕국의 치안, 빈곤, 자원량, 성격 분포에 따라 원인이 달라지는지 비교.
4. **관계의 이유:** 반복 사기·미상환·고용·보호 등 특정 사건을 NPC 기억과 장기 계획에 연결. 단순히 호감도만 높아지는 친목을 피할 것.
5. **시각적 변화:** 폐업, 신규 창업, 빈집 증가, 공급 부족을 지도에서도 알아볼 수 있게 표현.

## 6. 검증 방법과 범위

- 자동 시뮬레이션: `tests/simulate.mjs` (순수 Node.js, 별도 패키지 설치 불필요)
- GitHub Actions: 메인 브랜치 변경 시 10개 시드 × 30/90/180일 검증, 실패 시 체크 표시
- 테스트는 브라우저의 화면 렌더링과 실제 모바일 조작의 완전한 대체가 아니다.
- 정적 GitHub Pages는 서버에서 쉬지 않고 시뮬레이션을 실행하는 구조가 아니다. 브라우저를 열었을 때 실행되고 저장된 세계를 복원하는 방식이다.
