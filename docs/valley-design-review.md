# 산들계곡 플레이 구조 검토 — 2026-11-01

검토 대상: 기존 `d5f0e3e` 버전. 아래 수치와 진단은 관찰형 v2 구현 전의 기록이다. 새 구현은 [관찰형 세계](valley-observer-world.md)를 참고한다.

## 결론

현재 게임은 자동 생산·운반·건설을 구현했지만, 관리자가 결정해야 할 부족과 경쟁은 약하다. 최신 요청에 맞추려면 기존 세력의 네트워크와 우리 정착지의 고립을 구분하고, 같은 식량·노동·물류 제약으로 생존과 이웃의 흥망을 만들어야 한다. 이번 작업은 코드 검토와 시뮬레이션 실험이며 게임 규칙 변경이나 배포는 하지 않았다.

## 확인한 현재 동작

`js/valley-engine.js`를 Node에서 불러와 `fresh()` 후 하루당 `step(.2)`를 5회 실행했다. 별도 플레이어 명령 없이 720일을 관찰했다. '교역·이주 차단' 실험은 시작 때 두 설정만 끄고 이후 개입하지 않았다. 아래는 이 고정 세계의 실행 결과이며, 다양한 맵의 통계나 재미에 대한 사용자 검증은 아니다.

| --- | ---: | ---: | ---: | ---: |
| 공통 시작 | 12 | 2 | 20일 | 0 |
| 기본 방침 / 90일 | 12 | 4 | 83일 | 0 |
| 기본 방침 / 360일 | 43 | 12 | 167일 | 0 |
| 기본 방침 / 720일 | 87 | 24 | 375일 | 0 |
| 교역·이주 차단 / 360일 | 22 | 11 | 199일 | 0 |
| 교역·이주 차단 / 720일 | 34 | 20 | 460일 | 0 |

추가 관찰:

- 기본 실험에서 모촌 인구는 59→29로 줄지만, 주된 원인은 우리 마을로 54명이 이동한 것이다. 다른 네 이웃은 720일 동안 모두 인구가 늘었고, 다섯 이웃의 누적 기근 사망은 모두 0이었다. 기근 사망 규칙 자체는 존재한다.
- 시작 seed 1과 99999를 비교했지만 마을 인구·재고·건물 수가 같았다. RNG 함수가 실제 세계 변동에 사용되지 않는다.
- 도로는 렌더러가 모촌에서 모든 마을로 무조건 그린다. 실제 도로 상태·개척 비용·접촉 관계가 없다. 교역은 재고와 비축 조건만 맞으면 시작할 수 있고 수레는 모촌을 경유한다.
- 새 마을은 모촌의 인구·식량·목재·석재를 지원받고 시작하며, 교역과 이주가 처음부터 열린다. 최신 요청의 '어느 세력과도 아직 연결되지 않은 갑작스러운 정착지'와 다르다.
- 계절은 달력 표시이며 수확량을 바꾸지 않는다. 저장 용량·식량 부패·건물 유지비·도구 소모·질병·대외 갈등은 현재 경제에 없다.
- 주민 AI가 생존 우선 재배치뿐 아니라 성장 건물 선택까지 알아서 해결한다. 관리자의 네 가지 방침은 대부분 속도를 바꾸며, 지속적으로 감수할 비용과 포기하는 이익이 작다.

## 우선순위 1: 고립된 시작과 실제 연결망

기존 마을들에는 이미 만들어진 세력·교역 연결망을 주고, 우리 정착지는 그 그래프의 간선 없이 시작한다. 모촌의 자동 지원과 정기 이주를 새 시작에서 제외한다. 폐쇄된 교역 토글만으로 고립을 흉내 내지 않고, 발견·접촉·통행·계약 조건을 실제 데이터로 둔다.

첫 연결의 순서:

1. 정찰대를 보내 인접 지형과 마을을 발견한다. 보내는 동안 정착지의 생산 노동이 줄어든다.
2. 숲길·고개·나루 중 연결 방법을 정한다. 각 방법의 자재·노동·소요 기간과 취약점이 다르다.
3. 접촉한 마을과 거래를 제안한다. 상대 재고와 수요·조건에 따라 성립 여부가 달라진다.
4. 길이 통행 가능하고 거래가 성립한 뒤에만 도로와 수레가 나타난다. 끊긴 길은 물류에도 실제 영향을 준다.

지도에서 기존 세력의 길과 영토는 이어지지만, 우리 캠프에는 마지막 몇 킬로미터가 비어 있어야 한다. 알고 있는 마을의 정보도 정찰·교역 보고를 통해 갱신한다. 탐색하지 않은 곳도 백그라운드에서 계속 시뮬레이션한다.

## 우선순위 2: 첫 생존 결정을 만드는 식량·노동 제약

새 직업과 자원 종류를 늘리기보다 현재 식량·목재·주거·운반 루프를 먼저 재조정한다.

제안 시작 조건(아직 구현·밸런스 검증 전): 주민 8~12명, 임시 천막, 7~10일분 식량, 농장·시장·외부 길 없음. 직접 노동 지시는 유지하지 않고 관리자가 생존·주거·정찰에 노동과 자재 예산을 배정한다.

- 당장 식량을 모으면 수확 기반과 거처 공사가 늦어진다.
- 농장을 먼저 준비하면 일정 기간 먹을 것이 줄지만 이후 생산 기반을 얻는다.
- 정찰은 외부 공급 가능성을 열지만, 현재 생산할 인력이 줄고 실패 시 되돌릴 수 없는 시간을 잃는다.
- 주거와 창고를 미루면 비·추위·부패에 더 취약하다. 재고와 생산이 무한 누적되지 않도록 저장과 유지 비용을 연결한다.

주민은 일상 생산·운반·휴식과 승인된 사업의 실행을 자동 처리한다. 새로운 대형 사업, 외부 연결, 비축 방출, 인구 수용처럼 오래 영향을 미치는 결정은 관리자가 맡는다. 모든 건물마다 확인을 누르는 방식으로 바꾸지 않는다.

## 우선순위 3: 부족이 결정을 요구하는 화면

상단 자원 수량만으로는 무엇을 판단할지 알기 어렵다. 가장 시급한 실제 문제 2~3개와, 실행 가능한 대응을 게임 위에 표시한다.

예시(숫자는 향후 실제 상태·예측에서 계산해야 함):

> 식량 7일분 · 최근 생산보다 소비가 하루 2 많음
> 선택: 채집 강화 / 비축 배급 / 다음 공사 연기
>
> 탐색하지 않은 숲길 · 정찰 2개 조, 예상 4일
> 선택: 지금 출발 / 식량 14일분까지 보류

버튼에는 노동·자재·예상 기간·주요 위험을 같이 보여준다. 결과가 불확실한 정찰이나 기후는 범위와 불확실성을 표시한다. 정답 하나를 지시하는 퀘스트 목록이나 근거 없는 멸망 카운트다운을 만들지 않는다.

## 우선순위 4: 이웃의 흥망을 같은 경제에서 만들기

모든 마을을 정해진 주기로 강제 쇠퇴시키는 대신, 공급과 복구 능력이 달라지는 원인을 둔다. 첫 대상은 식량·교역로 의존이다.

예시 원인 사슬:

농촌의 흉작 → 수출 감소 → 식량 수입에 의존한 성채의 비축 소진 → 노동력 감소·이주 → 길과 시설 유지 지연 → 항구 교역량 감소.

피해는 실제 재고·노동·인구에 반영하고, 기록과 지도에 같은 원인을 보여준다. 폐업 시설·버려진 집·끊긴 수레·회복 중인 농지를 표시한다. 이주민은 출발지에서 차감하고 도착지에 더한다. 회복은 수확 개선·대체 교역로·이주·재투자를 통해 가능해야 한다.

우리에게도 난민 수용, 어려운 이웃에 물자 판매, 새로운 거래처 확보 같은 기회와 부담이 생긴다. NPC도 같은 제약 속에서 정책을 바꾸며 대응해야 하고, 무능하게 만들어서 쇠퇴를 연출하지 않는다.

## 다음 구현 범위와 판정 기준

먼저 고립 시작·연결망·초기 생존 판단을 한 흐름으로 만든다. 그 뒤 식량 공급 차질이 연결된 이웃으로 전파되는 규칙을 붙인다. 전쟁·종교·새 자원 다품종 확장은 뒤로 둔다.

검증 기준:

- 시작에 우리 마을로 향하는 도로·교역 수레·자동 지원이 없다.
- 무개입 시 식량과 주거의 실제 문제를 겪지만, 검증된 두 가지 이상의 운영 선택으로 생존할 수 있다.
- 첫 10분에 비용과 결과가 다른 관리자 결정이 세 번 이상 나온다. 각 결정의 효과를 지도·재고·사건 기록에서 추적할 수 있다.
- 특정 공급 차질 실험에서 연결된 마을이 타격을 받고, 대체 공급을 확보하면 회복한다. 사망과 이주를 구분하고 인구·물자 보존을 계속 확인한다.
- 출발 조건과 기후가 다른 여러 세계에서 결과가 달라지며, 무조건 번영하거나 무조건 멸망하는 단일 경로가 되지 않는다.
- 초기 생존 이후에도 유지 비용·노동·저장·연결망이 성장의 제약으로 남는다.
