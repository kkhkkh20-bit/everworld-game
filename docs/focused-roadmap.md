# 개발 범위 제한과 레퍼런스 기반 기획

조사일: 2026-10-23. 공식 소개·기능 문서를 읽고 설계 원리를 비교했다. 아래는 직접 플레이 검증이나 모든 최신 기능의 평가가 아니다.

## 재미에 대한 가설

**내가 기억하는 마을이 변하고, 그 이유를 이해하며, 다음 결과를 예상해 보는 재미**에 집중한다. 다음 10분을 더 관찰할 이유는 새 버튼이 아니라 ‘저 마을은 버틸까?’, ‘저 국경은 전쟁이 될까?’, ‘멸망한 곳이 다시 살아날까?’라는 구체적인 궁금증이다. 이 가설은 플레이 관찰로 검증해야 하며 재미가 확보됐다고 선언하지 않는다.

공식 설명에서 얻은 설계 제안이며, 해당 게임의 UI나 코드를 복제한다는 뜻은 아니다.

## 확정한 최소 핵심

1. 지도가 끊기지 않고 이동·확대되고 마을 선택이 안정적으로 동작한다.
2. 시간 진행·일시정지·건너뛰기·중단·저장이 신뢰할 수 있다.
3. 성장·쇠퇴·위기·전쟁·멸망의 변화가 지도와 짧은 비교 카드로 연결된다.
4. 관심 마을을 다시 찾을 수 있고, 그 마을의 기록이 끊기지 않는다.

건설·정책·군사·가문 등 기존 저장과 기능은 보존한다. 하지만 핵심 네 가지가 안정화되기 전에는 그 시스템의 종류와 메뉴를 늘리지 않는다. 새로운 개인 플레이 모드, 종교, 기술 계통, 자원·직업, 전술 조작, 추가 종족은 보류한다. 맵 크기와 생성 마을 상한도 더 늘리지 않는다.

## 다음 기능은 세 가지로 제한

### P0. 원인별 변화 장부

인구 변화부터 시작한다. 출생·사망·이주·전쟁·개척 이동의 실제 처리 지점에서 원인 코드와 증감을 기록한다. UI는 ‘80 → 74명: 출생 +2, 전사 -3, 이주 -5’처럼 장부 합계가 인구 증감과 맞는 경우만 분해한다. 검증 기준: 매 기간 기초 인구 + 순변화 = 기말 인구. 이전 저장의 미기록 구간은 추정하지 않는다.

이 기능이 먼저 필요한 이유: 현재 ‘인구 감소’는 보여도 어떤 사건이 얼마나 영향을 줬는지 확정하기 어렵다. 다른 기능보다 관찰의 설명력을 직접 높인다.

### P1. 세 장면으로 보는 중요한 사건

국경 접촉 → 분쟁 또는 교역 → 전투·협정·점령의 여파를 하나의 사건 ID로 묶는다. 동시에 강조하는 사건은 세 개 이하, 한 사건의 화면도 현재 상황·직접 원인·결과 세 항목으로 제한한다. 신규 세계에서도 실제 조건이 형성될 때만 사건을 만든다. 평온한 시기에는 성장 요약과 다음 사건까지 이동을 제공한다.

검증 기준: 지도와 카드가 같은 사건 ID와 당사자를 가리킨다. 진행이 끝나면 진행 중 표식이 사라지고 결과 기록은 남는다. 임의의 문장으로 인과관계를 만들어내지 않는다.

### P2. 제한된 개입과 결과 비교

생활 지원·건설 방향·외교 선택 세 부류 안에서 기존 명령을 정리한다. 원인 장부가 준비된 뒤에 명령의 비용, 완료·실패 이유, 관련 결과를 연결한다. 반대 선택의 결과를 계산하지 않았다면 ‘이 명령 때문에 반드시 이렇게 됐다’고 단정하지 않는다.

## 출시·확장 기준

- 기본 세계와 오래 진행한 저장 모두에서 프로파일링한다. 초기 6개 마을 측정만으로 대규모 세계 성능을 보장하지 않는다.
- 목표: 대표 모바일 조건에서 지도 조작 p95 프레임 간격 50ms 이하, 버튼 응답 100ms 이하. 24배속도 이 목표를 지향하되, 실제 시뮬레이션 처리량과 표시 배속을 구분해 측정한다.
- 시간 건너뛰기는 도중 중단 후 인구·자원·저장 상태가 유효해야 한다.
- 관찰 카드가 보여주는 숫자와 시뮬레이션 원본이 일치해야 한다.
- 10분 플레이에서 관심 마을 하나의 변화를 발견하고, 이유를 찾아 설명하고, 다음 관찰을 스스로 선택할 수 있는지 확인한다. 이 부분은 실제 사용자 관찰이 필요하다.
- 기준에 못 미치면 기능을 추가하지 않고 해당 병목을 먼저 고친다. 내부 검증 표본은 초기 6개, 중기 약 12~20개 마을을 포함하고, 더 큰 기존 저장은 별도 스트레스 대상으로 다룬다.

## 리팩토링 원칙

한 번에 전체를 재작성하지 않는다. 먼저 시뮬레이션 상태·화면 갱신·지도 캐시의 경계를 분리하고 결과 동일성을 확인한다. 그 뒤 파일 분리를 진행한다. 지금의 단일 HTML 실행 구조를 즉시 ES 모듈로 전환하면 저장 이행과 테스트 진입점까지 동시에 바뀌므로 이번 성능 수정을 위한 필수 범위에서 제외한다.
