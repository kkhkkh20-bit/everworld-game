# 성능 리팩토링 검토

2026-10-23. 기능은 추가하지 않고 렌더링과 갱신 경계를 정리했다. 게임 규칙, 기존 저장, 인구·경제·전투 결과를 바꾸는 최적화는 하지 않았다.

## 확인한 낭비와 변경

- 기존 `render()`가 숨긴 예전 주민·가구·역사 패널까지 갱신했다. 현재 지도 HUD 갱신과 `renderLegacyPanels()`를 분리하고 상세 패널을 열었을 때만 이전 패널을 갱신한다.
- 지형 캐시가 `cartography`에 연결되어 영토 변화마다 전체 지형을 다시 래스터화했다. 지형 캐시의 키는 세계 시드·크기·지형 버전·에셋 준비 상태로 제한했다. 세계 관찰 모드에서 쓰지 않는 탐색 안개 색칠도 제거했다.
- 영토 색과 국경은 `surfaceTerritoryLayer()`의 별도 캔버스에 저장한다. 영토 변경, 마을 멸망·소속 변경, 맵 크기 변경 때 새로 그린다.
- 숨긴 미니맵의 반복 그리기를 호출 경로에서 제외했다. 기존 저장과 호환되는 코드를 무작정 삭제하지 않았다.
- 일시정지 화면은 반복 그리지 않는다. 카메라·선택·시간·영토 표시가 바뀌거나 사용자가 조작하면 갱신된다. 브라우저가 숨겨진 경우 시각 프레임 작업을 건너뛴다.
- 보이지 않는 들녘 주민의 시각적 이동 계산을 하지 않는다. 인구·생계 시뮬레이션은 계속되며 다시 마을에 들어가면 실제 현재 행동에 맞춰 움직인다.
- 시각적 이동 계산을 페인트 주기와 맞추고, 고배속 정보 갱신은 200ms 간격으로 제한했다. 시뮬레이션 날짜나 자원 결과를 건너뛰지 않는다.
- 지도 이름표는 배치가 바뀔 때만 재배치한다. 글자 폭을 먼저 읽고 위치를 나중에 적용하여 읽기·쓰기를 섞어 발생하던 반복 레이아웃 계산을 줄인다.
- 마을 바닥의 동일 계절 판정을 프레임당 한 번 계산한다.
- 지도 맞춤의 최소 배율(.08)과 수동 확대·축소의 최소 배율이 달랐던 오류를 고쳤다. 축소 버튼이 되레 확대시키지 않는다.

## 검증과 측정 한계

`tests/render-budget.cjs`에서 멈춘 지도 700ms 동안 반복 draw가 0회인 것, 확대·축소 즉시 반영, 영토 변경 시 지형 캔버스 재사용과 국경 캔버스 교체, 숨긴 주민 패널·미니맵 호출 0회, 재생 후 주민 이동을 확인했다.

`tests/resident-activity.cjs`에서 작업 범위 내 주민 활동, 일시정지 시 정지, 여러 마을 이동, 원래 마을 멸망 뒤 다른 마을의 이동, 경제·난수 불변을 확인했다. 관찰 UI, 실제 교역, 배속 중 버튼 유지, 시간 건너뛰기, 공성 UI 및 10개 세계 시뮬레이션 회귀 테스트도 통과했다.

원시 측정은 `docs/performance-review.json`에 있다. Chromium 모바일 크기 화면, CPU 4배 제한, 시나리오별 4초 대기를 사용했다. 초기 세계는 같은 시드로 전후 비교했고, 약 5년 지난 12개 마을 저장도 별도 측정했다. 다른 CPU 집약 테스트와 순차 실행했지만 공유 호스트의 지연 변동은 남는다. rAF 간격은 캔버스 FPS가 아니며 일시정지 중에는 그림을 전혀 갱신하지 않으므로 두 수치를 혼동하지 않는다.

일시정지 시 불필요한 작업 제거는 호출 횟수로 확인됐다. 4배 제한 환경의 24배속에서는 개편 뒤에도 p95 콜백 간격이 초기 세계 300–517ms, 중기 세계 283–667ms로 목표 50ms에 미달했다. 이번 변경을 ‘렉 완전 해결’로 평가하지 않는다. CPU 제한 없는 별도 실행에서는 24배속 세계 100ms, 마을 33ms였다. 단일 실행의 전후 숫자를 보편적인 성능 향상률로 주장하지 않는다.

## 다음 성능 작업의 제한된 범위

새 기능보다 먼저 시뮬레이션의 하루 처리 비용과 저장 직렬화 비용을 분리 측정한다. 그 결과를 바탕으로 DOM을 참조하지 않는 시뮬레이션 진입점을 만들고, 필요한 경우 Web Worker로 이동한다. 이 과정은 난수 순서·저장 상태·중단 가능성의 동일성을 보장한 뒤 진행한다. 이번에는 고배속을 빠르게 보이게 하려고 실제 날짜나 사건 계산을 생략하지 않았다.

재현:

```sh
node tests/render-budget.cjs
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium node tests/resident-activity.cjs
PERF_CPU=4 PERF_OUT=/tmp/perf.json node tests/performance-review.cjs
PERF_CPU=4 PERF_SAVE=/path/to/save.json PERF_OUT=/tmp/perf-mature.json node tests/performance-review.cjs
node tests/simulate.mjs
```

성능 비교 시 다른 테스트와 동시에 실행하지 않는다. 이후 측정 스크립트는 실제 측정 경과 시간도 함께 출력한다.
