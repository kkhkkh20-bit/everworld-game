# 2026-10-22 장기 시뮬레이션 점검

## 범위와 재현 조건

사용자 화면의 1873년 기아 멸망과 반복된 멸망 기록을 보고 실제 일 단위 계산을 재실행했다. 사용자의 기기 저장 데이터는 접근할 수 없으므로 같은 저장을 재생했다고 주장하지 않는다.

수정 전 엔진은 `a31e71f72da26a99b5bc9d58fbaf88d818b9f523`. 예전 18명 시작 버전 `91f28e70f3790aa339ee955b6e135b9742146748`에서 시드 1840, 1, 7의 저장을 생성해 각각 수정 전·후 엔진으로 로드했다. 날짜·주민·식량·RNG를 임의로 바꾸지 않았다. 수정 전에는 최대 40년을 요청했으나 세 번 모두 25년 안에 멸망했다. 수정 후에는 세 조건 모두 30년(10,950일)을 계산했다. 중간 수정안에서 실제 재고 교역으로 바꾼 뒤 한 조건이 다시 멸망했고, 이를 통해 고정된 저장고 한도의 추가 결함을 찾았다. 아래는 그 중간 결과가 아닌 최종 수정안의 결과다.

그리기·자동 저장·실시간 타이머만 끄고 실제 `dailyStep`을 호출했다. 사회, 결혼, 출산, 노화, 농업, 저장, 정치, 이주, 교역, 전투와 인접 마을 계산은 유지했다. 표의 기아·출생·노환은 시작 이후 누적 인원이다. 초기 18명보다 누적 사망이 많은 것은 출생과 이주가 있기 때문이다.

## 확인하고 고친 결함

- 흉작 피해율 8–30%를 남는 수확 비율로 사용하고, 생장에도 같은 작은 값을 곱했다. 이제 30% 피해이면 수확은 정상의 70%이며 생장 지연은 별도로 작게 적용한다.
- 건강 22 미만 주민은 일을 쉬어도 식사 후 회복 경로가 없어 노동에 복귀하지 못했다. 충분히 먹고 수면·갈증 조건을 충족하면 나이에 따른 상한까지 천천히 회복한다. 개인·가구의 온전한 식사에 공동 배급 부족의 건강 벌점을 주던 것도 수정했다. 부족할 때 어린이와 쇠약자를 먼저 배급한다.
- 인구가 늘어도 저장고가 최대 3개여서 수확 때 버린 식량 때문에 다음 수확 전 붕괴했다. 인구의 약 300일 소비량을 기준으로 미리 저장고를 계획하고, 건설 한도를 인구에 맞춰 늘렸다. 기존 재료 비용·공사 기간·개당 저장량은 유지한다.
- 파종 시 곡물 유무를 확인한 다음 일반 식품 인출 함수로 우유 등을 먼저 소비했다. 실제 곡물을 종자로 분리 보관하고 파종에 차감한다. 극심한 식량난에서는 종자를 식량으로 풀되 다음 파종 여력이 줄어든다.
- 산림에서 수확할 것이 없어도 비상 채집이 하루를 소모했다. 무수확 강제 작업을 막고, 익은 밭이 있을 때는 실제 수확을 돕는다.
- 위기 정책이 목재를 소비하고 식량을 만들어 냈다. 우호적인 이웃에 거래 가능한 실제 여분 식량이 있을 때만 기존 교역으로 교환한다. 양측 식량·목재 총량 보존을 검사했다.
- 직접 멸망 판정과 월별 관찰이 같은 멸망을 중복 기록했다. 회차별 한 번만 기록하고, 불러올 때 35일 이내 동일 문구의 예전 중복만 정리한다. 원인·누적 사망·마지막 공동 비축을 표시하고 살아 있는 다른 마을로 이동하는 버튼을 추가했다.

## 검증과 한계

`tests/famine.cjs`는 30% 피해 시 약 70% 실제 수확·성장 완료, 먹고 회복한 주민의 실제 작업 복귀, 개인 식사, 비상 수확, 실재 재고 교역, 종자 분리/파종/비상 방출의 보존, 재료를 지불한 네 번째 저장고 계획, 고립 시 실제 기아 사망, 중복 기록 정리, 다른 마을로의 터치 이동과 주민 부활 없음 등을 Chromium에서 확인한다.

`tests/society.cjs`의 재산 보존·결혼·세대·분가·연합·선거·900일 자연 실행 및 `tests/map-surface.cjs`의 실제 지도 선택·마을 이동·교역·훈련·30일 건너뛰기·100년 건너뛰기 중단·모바일 입력·저장 복원도 확인했다. `tests/long-horizon.cjs`의 월별 재고 원장·유한값·생존 건강 검사는 1년 실행으로 별도 검증했다.

재실행 예:

```sh
# 최신 64명 시작, 기본 시드 1840/1/7, 각 30년. 결과는 기본적으로 OS 임시 폴더.
node tests/long-horizon.cjs
# 예전 18명 저장을 생성하는 원본 HTML을 받아 같은 조건 비교.
curl -fsSL https://raw.githubusercontent.com/kkhkkh20-bit/everworld-game/91f28e70f3790aa339ee955b6e135b9742146748/index.html -o /tmp/everworld-18.html
LEGACY=/tmp/everworld-18.html SEEDS=1840,1,7 YEARS=30 OUT=/tmp/everworld-legacy-30.json node tests/long-horizon.cjs
# 수정 전 엔진도 비교하려면 해당 버전 HTML을 받아 EVERWORLD_HTML로 지정.
```

세 개의 예전 시작 조건과 한 개의 현재 시작 조건에 대한 30년 결과다. 모든 시드나 100년 균형, 모든 전쟁 상황을 보장하지 않는다. 교역 차단·자원 고갈·고립·전투 피해로 실제 멸망할 수 있다. 이미 전원 사망한 사용자의 저장을 되살리거나 재화를 주입하지 않는다. 다른 마을은 기존 집계 시뮬레이션이며 원래 마을과 같은 개별 주민 가계 모델이 아니다. 기록된 멸망은 보존하고 다른 살아 있는 마을의 세계 관찰을 이어갈 수 있다.
