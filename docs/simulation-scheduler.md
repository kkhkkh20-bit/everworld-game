# 시뮬레이션과 브라우저 작업의 경계

2026-10-23. 문명 관찰 기능의 추가 확장은 보류하고 하루 계산·화면 갱신·저장 호출을 분리했다. Web Worker로 옮긴 작업은 아니다. 계산과 저장 직렬화는 아직 메인 스레드에서 실행한다.

## 변경

- `dailyStep()`은 하루 규칙과 관찰 표본을 처리한다. 주간 자동 저장을 내부에서 제거했다. 규칙의 실행 순서, 난수 순서, 하루 단위 상태는 유지한다.
- 브라우저의 `advanceSimulationDay()`는 완료된 하루 이후 화면 갱신 표시와 저장 예약만 한다. 동기적으로 지도나 정보를 그리지 않는다.
- 배속 타이머는 한 콜백에 하루만 처리한다. 기존 50ms 타이머에서 최대 8일을 묶던 방식 대신 16ms 간격으로 실행 기회를 확인한다. 처리할 예산이 없으면 계산하지 않는다. 대기량은 8일로 제한하고, 일시정지·세계 교체 때 비운다. 기기가 느리면 실제 진행은 표시 배속에 미달할 수 있으며 날짜를 생략하지 않는다.
- 정보 갱신은 애니메이션 프레임에서 최대 200ms 간격으로 한다. 계산 타이머의 추가 `render()`를 제거해 자동 재생 중 지도를 이중으로 그리지 않는다. 사용자의 직접 선택·확대·축소는 즉시 반영한다.
- 주간 자동 저장 요청은 하나로 합치고 실제 시간 기준 최소 5초 간격으로 제한한다. 가능하면 브라우저 유휴 시간에 실행하며 1초 타임아웃을 둔다. 수동 저장·개입·건너뛰기 종료·페이지 이탈은 기존 즉시 저장을 유지한다. 탭이 숨겨질 때도 저장한다. 저장 실패 처리는 기존 방식과 같다.
- 대기 중 저장은 세계 객체를 확인하고, 수동 저장이 이루어지면 취소한다. 새 게임 뒤 오래된 세계를 덮어쓰지 않는다.
- 시간 건너뛰기도 하루마다 이벤트 루프에 제어를 돌려준다. 중단 때 이미 완료한 날짜까지만 저장한다. 큰 건너뛰기는 타이머 양보 비용으로 총 처리 시간이 늘 수 있다.

## 측정 결과와 한계

`simulation-scheduler-performance.json`에 원시 수치를 보관했다. CPU 4배 제한, 초기 세계, 다른 CPU 테스트와 동시에 실행하지 않은 단일 표본이다. 각각 약 4초 동안 세계 지도 진행은 수정 전 21일, 수정 후 27일이었다. 자동 저장은 세계·마을 각각 3회에서 1회로 줄었다. 자동 계산 타이머에서 호출하던 `render()`는 수정 후 0회였다.

프레임 콜백 p95는 세계 지도 467→350ms, 마을 400→650ms였다. 마을 표본은 더 나빴으며, 이것을 전반적인 체감 성능 개선으로 주장할 수 없다. 수정 후에도 하루 계산 최대 154–225ms, 저장 최대 61–74ms의 긴 작업이 남았다. 이번 변경의 검증된 성과는 계산·화면·저장의 경계와 중복 호출 제거다. 50ms 목표 달성이나 모바일 렉 해결이 아니다.

약 5년 진행한 12개 마을 저장도 별도로 측정했다. 약 4초 동안 세계 지도는 12일, 마을은 23일 진행했고 프레임 콜백 p95는 각각 500ms, 267ms였다. 저장은 각 1회였지만 최대 277ms가 걸렸다. 저장 횟수를 줄이는 것만으로 저장 자체의 정지를 없앨 수 없다는 한계도 확인했다.

다음 병목은 하루 자체의 계산과 마을의 정적 그림 반복 처리다. 엔진 전체를 Worker로 이동하려면 상태 소유권·명령 전달·저장·새 게임 취소 규칙을 먼저 마련해야 한다. 가짜 DOM으로 전체 HTML을 Worker에서 실행하는 우회는 추가하지 않았다.

## 검증

- `REFERENCE_HTML=/path/to/previous.html node tests/simulation-boundary.cjs`: 시드 1840, 7 각각 365일, 수정 전후 전체 세계 상태 동일. DOM 조회 없이 하루 계산 실행.
- `node tests/simulation-scheduler.cjs`: 계산 중 그림·저장 호출 없음, 저장 요청 병합, 세계 교체/수동 저장 시 취소, 일시정지, 건너뛰기 취소 후 완료 날짜 저장. 가상 시계에서는 유휴 콜백을 타이머로 대체한다.
- `tests/render-budget.cjs`, `tests/observer-ui.cjs`, `tests/play-review.cjs`: 정지 화면·지도 조작, 결과 비교, 실제 교역, 24배속 버튼, 날짜 건너뛰기.
- `tests/resident-activity.cjs`, `tests/simulate.mjs`: 주민 이동과 장기 시뮬레이션 회귀.

성능 재현은 `PERF_CPU=4 PERF_OUT=/tmp/perf.json node tests/performance-review.cjs`로 실행한다. 오래된 저장은 `PERF_SAVE=/path/to/save.json`을 추가한다. 다른 CPU 테스트와 순차 실행해야 한다.
